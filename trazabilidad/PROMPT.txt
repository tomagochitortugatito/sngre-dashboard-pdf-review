Voy a adjuntar un archivo ZIP que contiene reportes de monitoreo de la Secretaría Nacional de Gestión de Riesgos del Ecuador en formato TXT.

Procesa TODOS los archivos `.txt` contenidos en el ZIP de forma independiente.

No combines información entre reportes y no utilices información de un TXT para completar otro TXT.

Para cada archivo TXT genera exactamente UN archivo JSON usando el mismo nombre base.

Ejemplo:

`reporte_0001.txt` → `reporte_0001.json`

Al finalizar, crea un único archivo ZIP llamado:

`SNGR_extracted_json.zip`

que contenga todos los JSON generados y un archivo `manifest.json`.

No pegues en el chat el contenido completo de todos los JSON. Trabaja directamente con los archivos y entrega el ZIP final.

# REGLAS GENERALES

Extrae cada reporte usando exactamente la estructura JSON indicada al final.

Devuelve información únicamente respaldada por el TXT correspondiente.

No inventes datos.

No agregues, elimines ni renombres claves del schema, excepto las claves numéricas dinámicas de `section_2.zones`.

Conserva el contenido extraído en español y las claves JSON en inglés.

Los campos `original_narrative` deben conservar fielmente el contenido correspondiente del reporte, sin resumirlo ni reinterpretarlo.

No uses conocimiento geográfico, institucional o externo para completar datos que no estén explícitamente presentes en el reporte.

# PRESERVACIÓN DE CELDAS

Respeta el contenido explícito de cada celda de las tablas.

Si una celda contiene un número, conviértelo a número cuando sea inequívoco.

Ejemplo:

`115.03` → `115.03`

Si una celda contiene explícitamente:

`--`

devuelve exactamente:

`"--"`

Si contiene:

`---`

devuelve exactamente:

`"---"`

NO interpretes `--` ni `---` como:

- cero
- `null`
- cadena vacía
- dato inexistente

Una celda explícitamente marcada con `--` o `---` debe conservar ese símbolo porque puede tener un significado institucional diferente de una celda realmente vacía.

Si una celda está realmente vacía en el documento, utiliza:

`""`

El valor `0` solo debe aparecer cuando el reporte explícitamente indique cero.

No sustituyas un valor explícito por otro valor interpretado.

# FORMATO DE TABLAS

En toda estructura que contenga:

`"columns":[...]`

y:

`"rows":[...]`

cada elemento de `rows` DEBE ser un ARRAY cuyos valores correspondan exactamente y en el mismo orden a `columns`.

Ejemplo:

`"columns":["province","canton","name"]`

debe producir:

`"rows":[["Guayas","Daule","Río Daule"]]`

NO:

`"rows":[{"province":"Guayas","canton":"Daule","name":"Río Daule"}]`

No uses objetos con nombres de claves dentro de `rows`.

# VALORACIÓN / ASSESSMENT

Cuando una celda de valoración contenga una categoría de color entre corchetes, elimina únicamente los corchetes y conserva la categoría.

Ejemplos:

`[VERDE]` → `"VERDE"`
`[AMARILLO]` → `"AMARILLO"`
`[AMARILLA]` → `"AMARILLA"`
`[ROJO]` → `"ROJO"`
`[ROJA]` → `"ROJA"`

No devuelvas los caracteres `[` o `]` en campos de valoración.

No infieras una valoración a partir de otros datos.

Si la valoración contiene explícitamente `--` o `---`, conserva exactamente `"--"` o `"---"`.

Si la celda está realmente vacía, utiliza `""`.

Esta regla aplica, entre otros, a:

- `current_assessment`
- `assessment`

# METADATA

Extrae únicamente:

- `report_name`
- `start`
- `end`
- `last_update`

Todas las fechas-horas utilizan:

`YYYY/MM/DD HH:MM:SS`

Las únicas ventanas válidas del período de monitoreo son:

`09:00:00 → 21:00:00`

o:

`21:00:00 → 09:00:00` del día siguiente.

Si `start` y `end` ya corresponden correctamente a una de estas ventanas, consérvalos aunque `last_update` sea posterior.

Si alguna hora de inicio o fin es distinta de 09:00 o 21:00, utiliza `last_update` y el contexto del reporte para corregir la ventana.

Cierre matutino:

`21:00` del día anterior → `09:00` del día actual.

Cierre nocturno:

`09:00` → `21:00` del mismo día.

Ejemplo:

Si el documento muestra:

inicio `01:00`

fin `09:00`

actualización `08:00`

normaliza el período a:

`21:00` del día anterior → `09:00` del día actual.

## SITUACIÓN HIDROMETEOROLÓGICA

Existe como máximo una situación, advertencia o aviso hidrometeorológico principal por reporte.

Cuando exista información, extrae:

### WARNING_NUMBER

`warning_number` representa únicamente el número explícito de la advertencia o aviso.

Extrae el número como entero y elimina ceros a la izquierda.

Ejemplos:

`ADVERTENCIA # 02` → `2`
`ADVERTENCIA # 005` → `5`
`ADVERTENCIA # 12` → `12`

No infieras el número a partir de otros reportes, fechas o secuencias.

Si no existe un número explícito, utiliza `null`.

### HAZARD

`hazard` es un objeto con cuatro componentes:

- `original`
- `primary_family`
- `phenomena`
- `associated_risks`

#### HAZARD.ORIGINAL

`hazard.original` conserva fielmente el texto que aparece como amenaza en el reporte, eliminando únicamente etiquetas estructurales como `AMENAZA:`.

Ejemplo:

`AMENAZA: LLUVIAS Y TORMENTAS.`

→

`"original":"LLUVIAS Y TORMENTAS."`

No corrijas errores ortográficos del texto original en `hazard.original`.

#### HAZARD.PRIMARY_FAMILY

`hazard.primary_family` representa la familia hidrometeorológica principal de la advertencia.

Solo puede tomar uno de estos SEIS valores:

`PRECIPITACION_TORMENTA`
`TEMPERATURA_ALTA`
`TEMPERATURA_BAJA`
`VIENTO_FUERTE`
`PRECIPITACION_SOLIDA`
`RADIACION_UV`

Estas seis familias representan:

- `PRECIPITACION_TORMENTA`: lluvias, lluvias intensas, tormentas y tormentas eléctricas.
- `TEMPERATURA_ALTA`: alta temperatura, incremento o aumento de temperatura diurna.
- `TEMPERATURA_BAJA`: descenso o baja temperatura nocturna o de madrugada.
- `VIENTO_FUERTE`: viento fuerte, incremento de la velocidad del viento o ráfagas.
- `PRECIPITACION_SOLIDA`: nevadas o posibles nevadas.
- `RADIACION_UV`: radiación ultravioleta elevada.

Clasifica prioritariamente según el texto explícito del campo `AMENAZA:`.

Normaliza para esta clasificación errores ortográficos evidentes, diferencias de mayúsculas/minúsculas, singular/plural y pequeñas variaciones de redacción.

Ejemplos:

`LLUVIAS Y TORMENTAS` → `PRECIPITACION_TORMENTA`
`LLUVIAS Y TORMENTAS ELÉCTRICAS` → `PRECIPITACION_TORMENTA`
`LLUVIAS INTENSAS Y TORMENTAS ELÉCTRICAS` → `PRECIPITACION_TORMENTA`
`LUVIAS Y TOMENTAS ELÉCTRICAS` → `PRECIPITACION_TORMENTA`
`INCREMENTO DE TEMPERATURA DIURNA` → `TEMPERATURA_ALTA`
`AUMENTO DE TEMPERATURAS DIURNAS` → `TEMPERATURA_ALTA`
`DESCENSO DE TEMPERATURA NOCTURNA` → `TEMPERATURA_BAJA`
`BAJA TEMPERATURA NOCTURNA` → `TEMPERATURA_BAJA`
`RÁFAGAS DE VIENTO` → `VIENTO_FUERTE`
`INCREMENTO DE LA VELOCIDAD DEL VIENTO` → `VIENTO_FUERTE`
`RADIACIÓN ULTRAVIOLETA` → `RADIACION_UV`

Cuando una advertencia sea compuesta, selecciona como `primary_family` el fenómeno meteorológico que actúe como tema principal según el encabezado y la redacción original.

Ejemplo:

`LLUVIAS Y NEVADAS`

→ `primary_family = "PRECIPITACION_TORMENTA"`

y además incluye `NEVADA` dentro de `phenomena`.

No conviertas incendios forestales, inundaciones, desbordamientos, crecidas o deslizamientos en `primary_family`. Esos conceptos deben tratarse como riesgos asociados cuando corresponda.

Si existe una amenaza real pero no es posible asignarla razonablemente a una de las seis familias, conserva `hazard.original`, utiliza `""` en `primary_family` y no inventes una séptima familia.

#### HAZARD.PHENOMENA

`hazard.phenomena` es un array que identifica todos los fenómenos meteorológicos explícitamente presentes en la amenaza.

Utiliza únicamente estos valores cuando correspondan:

`LLUVIA`
`TORMENTA`
`TORMENTA_ELECTRICA`
`TEMPERATURA_ALTA`
`TEMPERATURA_BAJA`
`VIENTO_FUERTE`
`NEVADA`
`RADIACION_UV`

Puede contener uno o varios valores.

Ejemplos:

`LLUVIAS Y TORMENTAS`

→

`["LLUVIA","TORMENTA"]`

`LLUVIAS Y TORMENTAS ELÉCTRICAS`

→

`["LLUVIA","TORMENTA_ELECTRICA"]`

`LLUVIAS, TORMENTAS ELÉCTRICAS, RÁFAGAS DE VIENTO Y POSIBLES NEVADAS`

→

`["LLUVIA","TORMENTA_ELECTRICA","VIENTO_FUERTE","NEVADA"]`

`ALTA TEMPERATURA DIURNA Y RADIACIÓN UV`

→

`["TEMPERATURA_ALTA","RADIACION_UV"]`

No agregues fenómenos únicamente porque aparezcan de forma secundaria en la descripción si no forman parte de la amenaza comunicada.

#### HAZARD.ASSOCIATED_RISKS

`hazard.associated_risks` es un array separado de los fenómenos meteorológicos.

Utiliza riesgos asociados únicamente cuando estén explícitamente mencionados como riesgo, condición favorable, posible consecuencia o efecto asociado de la amenaza.

Utiliza únicamente estos valores cuando correspondan:

`INCENDIO_FORESTAL`
`CRECIDA_CUERPOS_AGUA`
`DESBORDAMIENTO`
`INUNDACION`
`DESLIZAMIENTO_MOVIMIENTOS_MASA`

Ejemplo:

`ALTA TEMPERATURA DIURNA Y PROBABLES INCENDIOS FORESTALES`

→

`"primary_family":"TEMPERATURA_ALTA"`
`"phenomena":["TEMPERATURA_ALTA"]`
`"associated_risks":["INCENDIO_FORESTAL"]`

Ejemplo:

`INCREMENTO DE LA VELOCIDAD DEL VIENTO Y CONDICIONES FAVORABLES A INCENDIOS FORESTALES`

→

`"primary_family":"VIENTO_FUERTE"`
`"phenomena":["VIENTO_FUERTE"]`
`"associated_risks":["INCENDIO_FORESTAL"]`

Ejemplo:

Si una advertencia por lluvias señala explícitamente zonas propensas a crecidas y desbordamientos:

`"primary_family":"PRECIPITACION_TORMENTA"`

y puede incluir:

`"associated_risks":["CRECIDA_CUERPOS_AGUA","DESBORDAMIENTO"]`

No interpretes la mera presencia de la palabra `incendio`, `inundación`, `deslizamiento`, `crecida` o `desbordamiento` como un evento ocurrido. Aquí solo se registran como riesgos asociados al boletín hidrometeorológico.

No agregues riesgos asociados que no estén explícitamente respaldados por el texto.

### VALIDITY_START Y VALIDITY_END

`validity_start` y `validity_end` representan las fechas de inicio y fin de vigencia de la advertencia.

Normaliza ambas fechas al formato:

`YYYY-MM-DD`

No incluyas la hora en estos campos.

Utiliza TODA la expresión de vigencia para completar de manera contextual las partes de la fecha que estén implícitas.

Ejemplo:

`VIGENCIA: desde 19H00 del 07 hasta las 16H00 del 11 de enero de 2026.`

→

`"validity_start":"2026-01-07"`
`"validity_end":"2026-01-11"`

Ejemplo:

`VIGENCIA: desde las 00H00 del 25 hasta las 22H00 del 28 de enero de 2026`

→

`"validity_start":"2026-01-25"`
`"validity_end":"2026-01-28"`

Cuando el mes y año aparezcan una sola vez al final de la expresión pero sea inequívoco que aplican tanto al inicio como al final, aplícalos a ambas fechas.

Si el período atraviesa un cambio de mes o año y el texto permite determinarlo inequívocamente, conserva las fechas reales correspondientes.

No inventes mes o año si la expresión no permite determinarlos razonablemente.

Si una de las fechas no puede determinarse, utiliza `""` únicamente para esa fecha.

### DESCRIPTION

`description` conserva íntegramente el contenido correspondiente a `DESCRIPCIÓN:` sin resumirlo.

### AFFECTED_AREAS

`affected_areas` es UN STRING que conserva íntegramente el contenido correspondiente a `Zonas Afectadas`, `Áreas Afectadas` o equivalente.

No lo estructures por región ni provincia.

### SOURCE

`source` conserva la fuente explícitamente indicada en el bloque, por ejemplo:

`INAMHI`

No infieras una fuente si no está indicada.

### ORIGINAL_NARRATIVE

`original_narrative` conserva íntegramente el bloque completo de Situación Hidrometeorológica, incluyendo advertencia, amenaza, vigencia, descripción, zonas afectadas y fuente.

Si el reporte NO contiene una situación hidrometeorológica real o el bloque no contiene información real:

- `warning_number` = `null`
- `hazard.original` = `""`
- `hazard.primary_family` = `""`
- `hazard.phenomena` = `[]`
- `hazard.associated_risks` = `[]`
- `validity_start` = `""`
- `validity_end` = `""`
- `description` = `""`
- `affected_areas` = `""`
- `source` = `""`
- `original_narrative` = `""`

No inventes una advertencia.

No escribas `"--"` en estos campos salvo que el documento muestre explícitamente `--` en ese campo.

## PELIGRO SÍSMICO

Extrae cada registro disponible.

Si la tabla contiene únicamente `--` o `---`, conserva esos símbolos en las celdas correspondientes.

`YYYY/MM/DD`

`YYYY/MM`

Si solo se conoce el año:

`YYYY`

`""`

`desde febrero del 2020`

debe producir:

`"event_start_date":"2020/02"`

# MANIFEST.JSON

Genera también un archivo:

`manifest.json`

con esta estructura:

{"total_txt":0,"processed_ok":0,"failed":0,"files":[{"source":"","output":"","status":"ok","error":""}]}

`total_txt` = número total de TXT encontrados.

`processed_ok` = cantidad procesada correctamente.

`failed` = cantidad que no pudo procesarse.

Cada archivo debe aparecer una vez dentro de `files`.

`status` solo puede ser:

`"ok"`

o:

`"failed"`

Para un archivo correcto:

`"error":""`
